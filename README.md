# tg-proxy-2: панель и Telegram-бот для Telegram WEB proxy

`tgpanel` добавляет к уже установленному [tproxy-server](https://github.com/telegramdesktop/tproxy-server)
веб-панель (на отдельном поддомене, по случайному пути, с логином и паролем) и Telegram-бота. Каждому
пользователю выдаётся личная ссылка на прокси; панель считает его трафик, ограничивает срок доступа и
сама, безопасно и с откатом, перестраивает конфигурацию прокси при любых изменениях.

Подробная спецификация: [PLAN.md](PLAN.md). Установка по шагам: [docs/INSTALL.md](docs/INSTALL.md).
Устройство кода: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Факты об апстриме: [docs/UPSTREAM.md](docs/UPSTREAM.md).

## Что это умеет

- **Пользователи**: создать одного, пачкой по счётчику или списком `имя; telegram id; комментарий`,
  отключить, включить, продлить, перевыпустить секрет, удалить; поиск, фильтры, сортировка, массовые действия.
- **Ссылки** показываются только после успешного применения конфигурации и только по явному «Показать»
  (в панели) или в личном сообщении бота. QR-код, ссылки `https://t.me/...` и `tg://...`.
- **Сроки**: 1 день / месяц / год / дата / без срока; по истечении пользователь отключается (данные и
  статистика сохраняются), перед этим бот напоминает; продление включает его обратно.
- **Трафик**: счётчики nftables по каждому пользователю, графики (минуты → часы → дни), онлайн-статус,
  «первое подключение» и «последняя активность».
- **Telegram-бот**: пользователь нажимает «Запросить доступ»; администратор одобряет в боте или в панели
  (или включён открытый режим выдачи); рассылки, чёрный список, управление пользователями из бота.
- **Импорт** профилей прежнего бота без смены ссылок: Telegram ID берётся из имён `user_<id>`.
- **Резервные копии** (ежедневные и перед каждым применением), восстановление, откат при сбое.
- **Диагностика и обслуживание**: `tgpanel doctor`, `repair`, `update`, `uninstall`.

## Как это устроено

```
 клиент Telegram ──https──► Caddy (443) ──┬─ /<случайный путь>/* ──► tgpanel 127.0.0.1:8090
                                          └─ остальное ───────────► tproxy-server (relay)
                                                                        │ профили u1, u2, ...
                                                                        ▼
                                            MTProxy-пулы 127.0.0.1:2400.. (до 16 секретов в процессе)

 tgpanel.service  (один процесс asyncio, root)
 ┌───────────────────────────────────────────────────────────────────────────┐
 │ веб-панель (uvicorn) │ бот (long polling) │ планировщик │ коллектор nft    │
 │                 services  ─►  apply-конвейер (бэкап, проверка, откат)      │
 │                 SQLite (WAL)  ·  SystemOps (systemctl, nft, файлы, http)   │
 └───────────────────────────────────────────────────────────────────────────┘
```

Любое изменение, затрагивающее прокси, выполняется одним **применением**: перерисовка `profiles.json`,
своей части `config.json`, пулов MTProxy и таблицы nft → резервная копия → проверка → атомарная замена →
перезапуск → проверка `/healthz` и `/readyz` → при любой ошибке полный откат. Несколько одновременных
операций выстраиваются в очередь и объединяются в одно применение.

## Требования

- Ubuntu 24.04 или Debian 13, x86_64, запуск от root.
- Уже установленный и работающий WEB proxy (tproxy-server, MTProxy, Caddy). Установщик проверяет это
  первым и, если чего-то нет, выходит с кодом 1, **ничего не изменив**.
- Отдельный поддомен для панели (не совпадающий с доменом прокси) с A-записью на этот сервер. DNS нужен
  до установки: иначе Caddy не получит сертификат Let's Encrypt.
- Токен бота от @BotFather и ваш Telegram ID (администратор).
- Свободные порты 2400–2463, 8900–8963 и 8090 на 127.0.0.1.
- Правило брандмауэра у провайдера: порты пулов (2400–2463) и 8900–8963 снаружи **не открывать**
  (на сервере их закрывает таблица nft, но защита у провайдера надёжнее).

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/barakov-dot/tg-proxy-2/main/install.sh -o install.sh
printf '%s\n' '<токен бота>' > /root/bot.token && chmod 600 /root/bot.token
sudo bash install.sh --panel-domain panel.example.com --bot-token-file /root/bot.token --admin-id 123456789
```

Аргументы: `--panel-domain`, `--admin-id`, `--bot-token` или `--bot-token-file` (токен можно передать и
переменной `TGPANEL_INSTALL_BOT_TOKEN`: в `ps` она не видна), необязательные `--panel-login`,
`--panel-password` (`TGPANEL_INSTALL_PANEL_PASSWORD`), `--ref <тег/коммит>`, `--yes`, `--import` /
`--no-import`, `--ignore-dns`, `--check-only` (только проверки, ничего не менять). Без аргументов
установщик задаёт вопросы с терминала.

Что делает установщик:

1. Проверяет root, ОС, архитектуру и наличие WEB proxy (до любых изменений).
2. Проверяет DNS домена панели, свободные порты, поддержку счётчиков nft, хеш бинарника relay.
3. Ставит пакеты (`python3-venv`, `git`, `sqlite3`, `nftables`), клонирует код в `/opt/tgpanel`, создаёт
   venv и ставит зависимости строго по `requirements.lock` с хешами.
4. Создаёт `/etc/tgpanel` (0700), `/var/lib/tgpanel`, `/var/backups/tgpanel`; делает **начальный бэкап**
   `pre-install` (не ротируется).
5. Генерирует случайный путь панели, логин и пароль (если не заданы); токен бота и секрет приложения
   записывает в `/etc/tgpanel/tgpanel.env` (0600).
6. Ставит таблицу nft и юниты systemd.
7. **Импорт старых профилей** (см. ниже).
8. Добавляет блок панели в Caddyfile, проверяет конфигурацию, перезапускает Caddy и ждёт сертификат.
9. Делает первое применение, запускает `tgpanel.service`, выполняет самопроверку.
10. Один раз показывает адрес панели, логин, пароль и путь к бэкапу `pre-install`. **Сохраните пароль**:
    потом его можно только заменить (`tgpanel reset-password`).

### Импорт профилей прежнего бота

Если в `profiles.json` уже есть профили (например `user_<telegram id>`), установщик покажет их и предложит
импортировать: Telegram ID берётся из имени профиля, **секреты и значит ссылки остаются прежними**.
Перед подтверждением остановите прежнего бота (иначе он продолжит менять `profiles.json` в обход панели:
панель это заметит и откажется перезаписывать без `--force-external`). Старый процесс MTProxy на порту
2398 после импорта остаётся запущенным вхолостую; отключить: `tgpanel legacy-mtproxy off`.
Если от импорта отказаться, существующие профили остаются в `profiles.json` нетронутыми и продолжают
работать вне панели; импорт доступен позже (страница «Импорт» или `tgpanel import`).

### Сертификат панели

Если для домена панели в хранилище Caddy уже есть действительный сертификат, он используется повторно и
новый не запрашивается (повторный запуск установщика сертификат не перевыпускает). Иначе Caddy получает
сертификат Let's Encrypt; установщик ждёт его до 2 минут. Не успел — установка не откатывается, Caddy
продолжит попытки сам (причины: DNS, порт 80, лимиты Let's Encrypt); код выхода 3 означает «ждём сертификат».

### Приватный репозиторий

Скачайте `install.sh` на свой компьютер и передайте на сервер (`scp`). Адрес клонирования задаётся
переменной `TGPANEL_REPO_URL`: лучше SSH-адрес с deploy-ключом только на чтение
(`TGPANEL_REPO_URL=git@github.com:OWNER/tg-proxy-2.git sudo -E bash install.sh ...`). Адрес вида
`https://<токен>@github.com/OWNER/tg-proxy-2.git` тоже работает, но токен останется в `/opt/tgpanel/.git/config`:
используйте токен с правом только чтения этого репозитория.

### Версии и теги

Без `--ref` ставится последний релизный тег `vX.Y.Z`; если тегов ещё нет, ставится движущаяся ветка `main`
(установщик предупредит). Для воспроизводимой установки укажите `--ref v0.1.0` или хеш коммита. Выбранный
режим запоминается: `tgpanel update` без аргументов следует ему; сменить версию: `tgpanel update --ref <тег>`.

## Первый вход

Откройте адрес из итогового сообщения установщика: `https://<домен панели>/<случайный путь>/`.
Напомнить адрес: `tgpanel show-url`. Войдите логином и паролем из сообщения. Сессия живёт 12 часов;
кнопка «Выйти» завершает её сразу, «Выйти везде» в настройках завершает все сессии. Пароль меняется в
настройках или командой `tgpanel reset-password` (все прежние сессии при этом завершаются).

## Ежедневная работа

**Панель**: «Дашборд» (сводка, онлайн, трафик, состояние сервисов, срок сертификата) · «Пользователи»
(список, карточка с графиком трафика, массовые действия) · «Создать» · «Заявки» · «Рассылка» · «Импорт» ·
«Настройки» (режим выдачи, срок по умолчанию, пул, лимиты relay, интервал опроса, хранение статистики,
шаблоны сообщений, администраторы бота, токен бота, пароль) · «Бэкапы» · «Журнал» (аудит и история
применений). Во время применения вверху виден баннер; при ошибке — красный баннер с причиной,
система при этом остаётся в прежнем рабочем состоянии.

**Бот**: пользователь — `/start`, «Запросить доступ», «Моя ссылка», статус; администратор — `/admin`:
заявки (одобрить с выбором срока / отклонить), пользователи, рассылка, бэкапы, чёрный список, режим
выдачи (по заявкам или открытый). О сбое применения администраторам приходит сообщение.

**Командная строка** (на сервере, от root):

| Команда | Что делает |
|---|---|
| `tgpanel status` | сервисы, пользователи, пулы, последнее применение, расхождения |
| `tgpanel apply [--force-external] [--reload-nft] [--adopt] [--prune-orphans]` | пересобрать и применить конфигурацию |
| `tgpanel import [--dry-run] [--csv файл] [--id-regex выражение] [--yes]` | импорт профилей |
| `tgpanel legacy-mtproxy on\|off` | старый процесс MTProxy на 2398 |
| `tgpanel backup [--list] [--reason текст]` | резервная копия / список |
| `tgpanel restore <файл.tar.gz>` | восстановление из копии |
| `tgpanel doctor` | диагностика всех компонентов |
| `tgpanel repair` | вернуть блок Caddy, юниты, таблицу nft |
| `tgpanel update [--ref ...]` | обновить |
| `tgpanel uninstall [--purge] [--force]` | удалить и вернуть прокси к состоянию `pre-install` |
| `tgpanel show-url`, `tgpanel reset-password [--login ...]` | адрес панели / новый пароль |

## Ограничения, о которых стоит знать

- **Не более 16 секретов на процесс MTProxy** (ограничение официального MTProxy). Сверх этого панель сама
  создаёт следующий пул (процесс). Если проверка на сервере покажет, что 16-й секрет ломает процесс,
  понизьте «Секретов на процесс» до 15 в настройках.
- **Любое применение перезапускает relay, и все текущие клиентские сессии рвутся**; клиенты переподключаются
  сами. Поэтому массовые действия выполняются одним применением, а срочные правки лучше не дробить.
- **Трафик считается по счётчикам nftables**, то есть с учётом заголовков IP/TCP: цифры немного больше,
  чем «полезные» данные клиента. Это одинаково для всех пользователей.
- **«Первое подключение» и «последняя активность»** определяются порогом: за интервал опроса (по умолчанию
  30 с) должно пройти не меньше 2048 байт и 10 пакетов (меняется в настройках). Простое подключение без
  обмена данными активностью не считается; «онлайн» — активность в двух последних опросах подряд.
- Статистика хранится по минутам 14 дней, затем по часам 180 дней, затем по дням (настраивается).
- Полное удаление пользователя стирает и его статистику (в бэкапе она остаётся).

## Обновление

```bash
tgpanel update            # следует выбранному при установке режиму (последний релиз или --ref)
tgpanel update --ref v0.2.0
```

Повторный запуск `install.sh` тоже обновляет, не меняя путь, логин, пароль и секреты. Перед обновлением
делается копия, после — проверка запуска; при неудаче выполняется откат на прежнюю версию.

## Резервные копии и восстановление

Копия создаётся перед каждым применением, ежедневно (час настраивается) и по кнопке/команде. Копии лежат
в `/var/backups/tgpanel` (0600, каталог 0700), хранятся по правилу «последние N + по одной в день»;
`pre-install` не удаляется никогда. Восстановление: страница «Бэкапы» → «Восстановить» или
`tgpanel restore /var/backups/tgpanel/<файл>.tar.gz`. Восстановление заменяет базу и файлы прокси
содержимым архива и перезапускает relay.

## Удаление

```bash
tgpanel uninstall            # вернуть профили/конфиг из pre-install, убрать юниты, пулы, таблицу nft
tgpanel uninstall --purge    # то же и удалить данные (/var/lib/tgpanel, /etc/tgpanel)
```

Без копии `pre-install` команда откажется работать без `--force`. Каталог Caddy `/var/lib/caddy`
(сертификаты) не затрагивается никогда.

## Если что-то не так

```bash
tgpanel doctor                     # проверки сервисов, портов, DNS, сертификата, nft, расхождений
tgpanel repair                     # вернуть блок Caddy, юниты и таблицу nft (делает копию)
journalctl -u tgpanel -n 200       # журнал службы (секреты и токены в нём замаскированы)
systemctl status tgpanel caddy tproxy-server
```

Типичные случаи:

- **Панель не открывается, браузер ругается на сертификат**: сертификат ещё не выпущен. `tgpanel doctor`
  покажет причину (DNS, порт 80, лимиты Let's Encrypt).
- **Красный баннер «последнее применение не удалось»**: прочитайте причину в «Журнале → Применения»;
  прокси продолжает работать на прежней конфигурации. После устранения причины `tgpanel apply`.
- **`profiles.json` изменён вне панели** (например прежним ботом): `tgpanel import` (подхватить новые
  профили) или `tgpanel apply --force-external` (перезаписать). Служба не перезаписывает чужие правки молча.
- **Бот молчит**: в журнале будет заметная запись о неверном или пустом токене; задайте токен в настройках
  панели и перезапустите службу (`systemctl restart tgpanel`). Панель, коллектор и планировщик работают и без бота.
- **Служба не стартует и пишет про `TGPANEL_SECRET_KEY`**: ключ в `/etc/tgpanel/tgpanel.env` отсутствует
  или короче 32 символов; выполните `tgpanel repair` или переустановите.
- Проверка `/healthz`: `GET https://<домен>/<путь>/healthz` отвечает `{"ok": true}` без авторизации и
  без каких-либо данных.

## Безопасность

- Случайный путь панели — это только «безвестность», а не защита; защищает пароль. Пароль хранится как
  хеш argon2, число неудачных попыток входа ограничено (по клиенту и глобально), есть защита от CSRF,
  строгие заголовки (CSP и др.), сессионные cookie подписаны и ограничены путём панели.
- Панель слушает только `127.0.0.1`; наружу её выставляет Caddy. Access-логи Caddy выключены; в журналах,
  аудите и сообщениях об ошибках нет секретов пользователей, токена бота и ссылок.
- Служба работает от root (управляет systemd и nftables), внешние команды вызываются только списком
  аргументов; менять можно только `profiles.json`, раздел `limits` в `config.json` и свой блок Caddyfile.
- Закройте порты пулов и статистики на брандмауэре провайдера (см. «Требования»).
- Файл `/etc/tgpanel/tgpanel.env` (токен бота, ключ подписи сессий) доступен только root (0600).

## Проверка на сервере

`scripts/server-selfcheck.sh` (от root, лучше до или сразу после установки) проверяет то, что нельзя
доказать чтением кода апстрима: счётчики nft по элементам, предел секретов, работу MTProxy на адресах
`127.64.x.y`, поведение `systemctl mask`, память на процесс, сертификат панели. Остальное делается вручную
по чек-листу «Фаза 8» в [PLAN.md](PLAN.md) (раздел 11): подключение клиентом по 1-му и 16-му секрету, сбой
применения, перезагрузка сервера, `uninstall`, импорт 15 профилей, время от «Создать» до рабочей ссылки.

## Разработка

Только модульные тесты и линтеры; ничего из прокси не запускается. См. [CLAUDE.md](CLAUDE.md).

```bash
uv venv --python 3.12 ~/.venvs/tgpanel && uv pip install --python ~/.venvs/tgpanel/bin/python -e ".[dev]"
ruff check . && ruff format --check tgpanel tests && mypy && pytest -q && shellcheck install.sh scripts/*.sh
```
